3  Locally Weighted and Logistic Regression

Lecture 3

Keywords

locally weighted regression, logistic regression, maximum likelihood, Newton’s method, sigmoid function

Lecture video: Lecture 3: Locally Weighted and Logistic Regression · 1:19:34

Based on the lecture by Andrew Ng — CS229, Stanford University, Autumn 2018.

This lecture takes the linear regression of lecture 2 in three directions. Locally weighted regression keeps the least-squares machinery but refits it around every query point, which lets a straight-line method trace a curve no single set of features would fit. A probabilistic reading of linear regression then shows that least squares is not an arbitrary choice: it is what maximum likelihood gives when the noise is Gaussian. And the same two-step recipe — assume a distribution for yyy given xxx, then maximise the likelihood — produces logistic regression, the first classification algorithm of the course, along with Newton’s method to fit it in a handful of iterations. Ng ranks linear and logistic regression as the two learning algorithms he uses most.

3.1 Features, or a different algorithm

2:20 Lecture 2 fitted a straight line to house prices, but the data may bend. One answer is to change the features: fit θ0+θ1x+θ2x2\theta_0 + \theta_1 x + \theta_2 x^2θ0​+θ1​x+θ2​x2 by defining x2=x2x_2 = x^2x2​=x2, and the linear-regression machinery runs unchanged, because “linear” refers to the parameters, not to xxx. The trouble is choosing. A quadratic eventually curves back down, which for house prices says a bigger house is cheaper; x\sqrt{x}x​ or log⁡x\log xlogx might bend the right way; and for data that rise, dip and rise again, Ng says frankly that finding the right set of features — square root, log, cube, x2/3x^{2/3}x2/3 — is hard. Feature-selection algorithms that automate the choice come later in the course.

5:53 Locally weighted regression sidesteps the question, and it introduces a distinction worth having early. A parametric learning algorithm fits a fixed set of parameters, after which the training set can be erased: linear regression keeps only θ\thetaθ. A non-parametric algorithm has to keep the data, and the amount it stores grows — linearly here — with the size of the training set. That is the cost of not having to choose features, and it is why Ng warns that such methods may not suit a really massive dataset.

3.2 Locally weighted regression

8:33 Linear regression makes a prediction at xxx by fitting θ\thetaθ once to all the data and returning θ⊤x\theta^\top xθ⊤x. Locally weighted regression postpones the fit until it knows where the prediction is wanted. Given the query point xxx, it fits a straight line that pays most attention to the training examples with inputs near xxx, glances at the ones further away, and uses that local line to predict at xxx; a different query point gets a different line. Formally it chooses θ\thetaθ to minimise a weighted cost,

∑i=1mw(i)(y(i)−θ⊤x(i))2,w(i)=exp⁡ ⁣(−(x(i)−x)22τ2),(3.1) \sum_{i=1}^{m} w^{(i)} \left( y^{(i)} - \theta^\top x^{(i)} \right)^2, \qquad w^{(i)} = \exp\!\left( -\frac{\left(x^{(i)} - x\right)^2}{2\tau^2} \right), \tag{3.1}i=1∑m​w(i)(y(i)−θ⊤x(i))2,w(i)=exp(−2τ2(x(i)−x)2​),(3.1)

and returns θ⊤x\theta^\top xθ⊤x. 12:09 When x(i)x^{(i)}x(i) is close to the query the weight is near e0=1e^0 = 1e0=1 and that example’s error counts in full; when it is far the weight is near zero and its error term all but disappears from the sum. (Ng first wrote the exponent without the square on τ\tauτ; a student caught it, and it is τ2\tau^2τ2.) The left panel of Figure 3.1 shows one such fit.

15:27 The weight function is shaped like a Gaussian bell, and Ng heads off the obvious confusion: it has nothing to do with a Gaussian density. Its peak is 1, it does not integrate to 1, and it is not a probability of anything — just a convenient bump. The bump’s width is the bandwidth τ\tauτ, a hyperparameter, and 16:46 it decides how large a neighbourhood each local fit sees. Ng leaves its effect for the problem set, saying only that it controls overfitting and underfitting; the right panel of Figure 3.1 shows both. With τ=0.12\tau = 0.12τ=0.12 only a couple of points carry weight in each fit, and the curve chases the noise into spikes; with τ=4\tau = 4τ=4 nearly every point carries weight everywhere, and the curve flattens towards a single straight line. In the limit it is that line: the generator checks that a bandwidth of 10410^4104 reproduces the ordinary least-squares fit to four decimal places. At τ=0.6\tau = 0.6τ=0.6 the curve follows the rise, the dip and the plateau without being told what features describe them.

The questions that followed are the practical ones. Asked 18:53 about predicting outside the range of the data, Ng said the formulas still work but the results may be poor — locally weighted regression is not good at extrapolation, but then most learning algorithms are not. Asked about letting τ\tauτ vary across the input space, he said yes: there is a large literature on choosing it from the local density of points, and on replacing the bell with other shapes, such as a triangle that reaches zero outside a window. His own rule 19:58 is to reach for locally weighted regression when the number of features is small, two or three, there is a lot of data, and you do not want to think about which features to use.

20:29 On cost, his answer at the board needs one correction. Each prediction solves a weighted version of the normal equations, X⊤WXθ=X⊤Wy⃗X^\top W X \theta = X^\top W \vec{y}X⊤WXθ=X⊤Wy​ with WWW the diagonal matrix of weights, and that is a system of dimension n+1n + 1n+1 — the number of parameters — not of the number of training examples, as the lecture puts it. What does grow with mmm is the work of forming the system, since every training example contributes a weighted term, and that work is repeated for every query. So a prediction costs time proportional to mmm, which is why a few thousand examples are no problem and millions call for data structures such as k-d trees that find the nearby points without visiting all of them.

3.3 Least squares as maximum likelihood

22:24 Lecture 2 promised a reason for squaring the error. Ng’s answer starts by assuming how the data were generated: each house’s price is a linear function of its features plus an error,

y(i)=θ⊤x(i)+ϵ(i),ϵ(i)∼N(0,σ2),(3.2) y^{(i)} = \theta^\top x^{(i)} + \epsilon^{(i)}, \qquad \epsilon^{(i)} \sim \mathcal{N}(0, \sigma^2), \tag{3.2}y(i)=θ⊤x(i)+ϵ(i),ϵ(i)∼N(0,σ2),(3.2)

where ϵ(i)\epsilon^{(i)}ϵ(i) gathers everything the model leaves out — the seller’s mood that day, unmodelled features — and random noise. The density of the error is the Gaussian 12πσexp⁡ ⁣(−ϵ2/2σ2)\frac{1}{\sqrt{2\pi}\sigma}\exp\!\left(-\epsilon^2 / 2\sigma^2\right)2π​σ1​exp(−ϵ2/2σ2), which, unlike the bump of Section 3.2, does integrate to one. 25:45 The large assumption is that the errors are IID — independent and identically distributed across houses — and Ng is candid that it is false: if one house on a street is priced unusually high, its neighbours probably are too. It is one of those assumptions that is probably not true and is good enough to give a useful model.

Together the assumptions say that, given xxx and θ\thetaθ, the price is Gaussian around the line:

p(y(i)∣x(i);θ)=12πσexp⁡ ⁣(−(y(i)−θ⊤x(i))22σ2).(3.3) p\left(y^{(i)} \mid x^{(i)}; \theta\right) = \frac{1}{\sqrt{2\pi}\sigma} \exp\!\left( -\frac{\left( y^{(i)} - \theta^\top x^{(i)} \right)^2}{2\sigma^2} \right). \tag{3.3}p(y(i)∣x(i);θ)=2π​σ1​exp(−2σ2(y(i)−θ⊤x(i))2​).(3.3)

28:16 The semicolon is read “parameterised by”. Writing a comma would mean conditioning on θ\thetaθ, which is not a random variable in this frequentist view; Ng keeps the distinction, he says, mostly to avoid upsetting statistician friends, and admits it changes nothing about the code one writes.

30:57 Because the errors are independent, the probability of all the observed prices is the product of the individual densities, and viewed as a function of θ\thetaθ with the data fixed that product is the likelihood,

L(θ)=∏i=1mp(y(i)∣x(i);θ).(3.4) L(\theta) = \prod_{i=1}^{m} p\left(y^{(i)} \mid x^{(i)}; \theta\right). \tag{3.4}L(θ)=i=1∏m​p(y(i)∣x(i);θ).(3.4)

32:44 Ng’s vocabulary rule is worth adopting. The likelihood of the parameters and the probability of the data are the same number; which name you use says which argument you are varying. So one speaks of the likelihood of the parameters and the probability of the data, never the reverse.

37:49 Maximum likelihood estimation chooses the θ\thetaθ that makes the observed data most probable. The logarithm is strictly increasing, so it is easier and equivalent to maximise the log-likelihood ℓ(θ)=log⁡L(θ)\ell(\theta) = \log L(\theta)ℓ(θ)=logL(θ), which turns the product into a sum:

ℓ(θ)=mlog⁡12πσ−1σ2⋅12∑i=1m(y(i)−θ⊤x(i))2.(3.5) \ell(\theta) = m \log \frac{1}{\sqrt{2\pi}\sigma} - \frac{1}{\sigma^2} \cdot \frac{1}{2} \sum_{i=1}^{m} \left( y^{(i)} - \theta^\top x^{(i)} \right)^2 . \tag{3.5}ℓ(θ)=mlog2π​σ1​−σ21​⋅21​i=1∑m​(y(i)−θ⊤x(i))2.(3.5)

The first term does not involve θ\thetaθ, and σ2\sigma^2σ2 is a positive constant, so maximising ℓ\ellℓ is exactly minimising the least-squares cost J(θ)J(\theta)J(θ) of lecture 2 — and the answer does not depend on σ\sigmaσ at all. Least squares is maximum likelihood under IID Gaussian noise.

Asked 35:31 why the noise should be Gaussian, Ng pointed to the central limit theorem: an error made of many small, not-too-correlated contributions — the seller’s mood, the school district, the weather, transport — sums to something close to Gaussian, which is why it became the default. The same derivation also answers lecture 2’s question about absolute error, which Ng deferred. Assume instead that the errors follow a Laplace distribution, with density proportional to exp⁡(−∣ϵ∣/b)\exp(-|\epsilon|/b)exp(−∣ϵ∣/b), and the log-likelihood becomes a constant minus a multiple of ∑i∣y(i)−θ⊤x(i)∣\sum_i |y^{(i)} - \theta^\top x^{(i)}|∑i​∣y(i)−θ⊤x(i)∣: maximum likelihood is then least absolute deviations. The difference is not cosmetic. With an intercept alone the Gaussian answer is the mean and the Laplace answer is the median, and the generator checks both against a grid search on a sample of twenty values around 3 plus one at 25: the Gaussian estimate is pulled to 4.09 by the single outlier, the Laplace one stays at 2.93. The choice of noise model is a choice of how much to trust the extreme points.

Asked 41:07 whether some other cost would ever be better, Ng said that under these assumptions none is — the derivation makes least squares the answer. If you know the errors are badly non-IID, more sophisticated models exist, but in practice he rarely bothers: assumptions known to be not quite true are often kept because they make the algorithm efficient.

3.4 Why not linear regression for classification

43:42 The recipe — assume p(y∣x;θ)p(y \mid x; \theta)p(y∣x;θ), then maximise the likelihood — now goes to a problem where yyy is 0 or 1: binary classification, with lecture 1’s tumours as the example. The tempting shortcut is to fit a straight line to the 0/1 labels and call anything above 0.5 a 1. Ng’s objection 44:43 is a single extra example. Add one malignant tumour far to the right, a point whose label nobody would dispute, and the least-squares line tilts to reach it; the place it crosses 0.5 slides right, and malignant tumours that were correctly classified are now called benign. In Figure 3.2 the threshold moves from 3.17 to 4.11, and the number of misclassified tumours goes from one to three, because of a point that contained no new information about where the boundary is. There is also the unnatural fact that a line outputs values below 0 and above 1 for something that can only be 0 or 1. Ng says some people use linear regression for classification and sometimes get lucky; he never does.

3.5 The logistic model

46:46 A classifier’s hypothesis should output a number between 0 and 1, so logistic regression passes the linear function through the sigmoid or logistic function — the two names mean the same thing:

hθ(x)=g ⁣(θ⊤x)=11+e−θ⊤x,g(z)=11+e−z.(3.6) h_\theta(x) = g\!\left(\theta^\top x\right) = \frac{1}{1 + e^{-\theta^\top x}}, \qquad g(z) = \frac{1}{1 + e^{-z}} . \tag{3.6}hθ​(x)=g(θ⊤x)=1+e−θ⊤x1​,g(z)=1+e−z1​.(3.6)

ggg starts near 0 for very negative zzz, passes through 12\tfrac1221​ at z=0z = 0z=0 and approaches 1. Ng is open that he is pulling it “out of a hat” for now: many functions have that shape, and lecture 4 derives this one from the generalised linear model framework. Section 3.6 adds a reason of its own.

50:23 The probabilistic assumption is that the hypothesis is the probability of the positive class — the chance that the tumour is malignant:

P(y=1∣x;θ)=hθ(x),P(y=0∣x;θ)=1−hθ(x).(3.7) P(y = 1 \mid x; \theta) = h_\theta(x), \qquad P(y = 0 \mid x; \theta) = 1 - h_\theta(x). \tag{3.7}P(y=1∣x;θ)=hθ​(x),P(y=0∣x;θ)=1−hθ​(x).(3.7)

A student asked whether the roles could be swapped; they could, and nothing would change except which class is called positive. 52:46 Since yyy is 0 or 1, the two lines compress into one,

p(y∣x;θ)=hθ(x) y(1−hθ(x))1−y,(3.8) p(y \mid x; \theta) = h_\theta(x)^{\,y} \left(1 - h_\theta(x)\right)^{1 - y}, \tag{3.8}p(y∣x;θ)=hθ​(x)y(1−hθ​(x))1−y,(3.8)

because whichever factor carries a zero exponent becomes 1 and drops out, leaving the line that applies. The trick is only notation, but it is what makes the likelihood a single product.

3.6 Maximum likelihood and gradient ascent

56:03 With Equation 3.8 the likelihood is ∏ih(x(i))y(i)(1−h(x(i)))1−y(i)\prod_i h(x^{(i)})^{y^{(i)}} (1 - h(x^{(i)}))^{1 - y^{(i)}}∏i​h(x(i))y(i)(1−h(x(i)))1−y(i), and its log is

ℓ(θ)=∑i=1my(i)log⁡hθ ⁣(x(i))+(1−y(i))log⁡ ⁣(1−hθ ⁣(x(i))).(3.9) \ell(\theta) = \sum_{i=1}^{m} y^{(i)} \log h_\theta\!\left(x^{(i)}\right) + \left(1 - y^{(i)}\right) \log\!\left(1 - h_\theta\!\left(x^{(i)}\right)\right). \tag{3.9}ℓ(θ)=i=1∑m​y(i)loghθ​(x(i))+(1−y(i))log(1−hθ​(x(i))).(3.9)

To fit, 58:54 Ng uses batch gradient ascent: the same walk as lecture 2, but uphill, since the goal is now to maximise ℓ\ellℓ rather than minimise JJJ, so the minus sign in the update becomes a plus. Working out the derivative, which Ng leaves to the notes, gives

θj:=θj+α∑i=1m(y(i)−hθ ⁣(x(i)))xj(i).(3.10) \theta_j := \theta_j + \alpha \sum_{i=1}^{m} \left( y^{(i)} - h_\theta\!\left(x^{(i)}\right) \right) x_j^{(i)} . \tag{3.10}θj​:=θj​+αi=1∑m​(y(i)−hθ​(x(i)))xj(i)​.(3.10)

The generator checks this gradient against finite differences of Equation 3.9.

1:03:06 Ng then put a question to the room. Flip the sign and swap the two terms in the bracket, and Equation 3.10 is character for character the LMS rule of lecture 2 — yet the lecture had just argued that linear regression is wrong for classification. What changed? The hypothesis: hθh_\thetahθ​ is now g(θ⊤x)g(\theta^\top x)g(θ⊤x), not θ⊤x\theta^\top xθ⊤x, so the same-looking update does something different. The resemblance is not a coincidence; it holds for the whole family of generalised linear models, and Ng adds that the likeness caused priority disputes in the field’s early history, between people who thought the algorithms were one and people who saw they were not.

1:02:15 Asked whether ℓ\ellℓ has local maxima, Ng said no: for logistic regression the log-likelihood is concave, so the only maximum is the global one. The Hessian makes that checkable, ∇2ℓ=−∑ih(1−h) x(i)x(i)⊤\nabla^2 \ell = -\sum_i h(1-h)\, x^{(i)} x^{(i)\top}∇2ℓ=−∑i​h(1−h)x(i)x(i)⊤, a negative sum of outer products, and the generator confirms it is negative semidefinite at two hundred random parameter values. He then gave this as another reason to choose the logistic function over other S-shaped functions — that it guarantees a single maximum. That is true but not unique to it, and the generator says where the property actually comes from. ℓ\ellℓ is concave because log⁡g(z)\log g(z)logg(z) and log⁡(1−g(z))\log(1 - g(z))log(1−g(z)) are both concave in zzz, and that is a property of the S-curve, not of logistic regression. The normal CDF, which gives probit regression, has it too. The Cauchy CDF, 12+arctan⁡(z)/π\tfrac12 + \arctan(z)/\pi21​+arctan(z)/π, an S-curve with heavy tails, does not: its log bends upward in the left tail (Figure 3.3), and on a three-example dataset the resulting log-likelihood has positive curvature at θ=−0.9\theta = -0.9θ=−0.9, so the argument that rules out local maxima no longer applies. The logistic function is one of a class of choices with a single maximum, not the only one; its claim to being the choice is the generalised-linear-model derivation of lecture 4.

Asked 1:04:53 whether logistic regression has an equivalent of the normal equations, Ng’s short answer was no: there is no known closed form for the maximising θ\thetaθ, so an iterative method is always needed.

3.7 Newton’s method

1:05:36 Gradient ascent takes baby steps. Ng’s comparison is a problem that needs a hundred or a thousand gradient iterations and only ten of Newton’s method, each of which costs more. To explain it he solves a different problem first: given a function fff of a single real θ\thetaθ, find where f(θ)=0f(\theta) = 0f(θ)=0. Maximising ℓ\ellℓ is such a problem, since at the maximum ℓ′(θ)=0\ell'(\theta) = 0ℓ′(θ)=0, so in the end fff will be ℓ′\ell'ℓ′.

1:08:33 The picture is a sequence of tangents. From the current guess, draw the line tangent to fff and follow it down to where it crosses zero; that crossing is the next guess. Repeat, and within a few iterations the guesses sit on the root (Figure 3.4). If the tangent at θ0\theta_0θ0​ meets the axis a horizontal distance Δ\DeltaΔ away, its slope is the height over the run, f′(θ0)=f(θ0)/Δf'(\theta_0) = f(\theta_0) / \Deltaf′(θ0​)=f(θ0​)/Δ, so Δ=f(θ0)/f′(θ0)\Delta = f(\theta_0)/f'(\theta_0)Δ=f(θ0​)/f′(θ0​) and

θ(t+1):=θ(t)−f(θ(t))f′(θ(t))⟹θ(t+1):=θ(t)−ℓ′(θ(t))ℓ′′(θ(t)).(3.11) \theta^{(t+1)} := \theta^{(t)} - \frac{f\left(\theta^{(t)}\right)}{f'\left(\theta^{(t)}\right)} \quad\Longrightarrow\quad \theta^{(t+1)} := \theta^{(t)} - \frac{\ell'\left(\theta^{(t)}\right)}{\ell''\left(\theta^{(t)}\right)} . \tag{3.11}θ(t+1):=θ(t)−f′(θ(t))f(θ(t))​⟹θ(t+1):=θ(t)−ℓ′′(θ(t))ℓ′(θ(t))​.(3.11)

The update uses only where ℓ′\ell'ℓ′ vanishes, so it is the same whether the goal is a maximum or a minimum — the official notes leave this as a question, and that is the answer. What makes it the right tool here is that ℓ\ellℓ is concave, so its only stationary point is the maximum.

1:14:22 The speed has a name, quadratic convergence, which Ng calls “not a great name”. Informally, once Newton’s method is close, the error is roughly squared at each step: an error of 0.01 becomes about 0.0001 and then about 0.00000001, so the number of correct digits doubles per iteration. On the problem of Figure 3.4 the generator’s errors run 0.053, then 0.0014, then 9×10−79 \times 10^{-7}9×10−7. The doubling only starts near the root; from the start at zero the first few steps shrink the error more slowly.

1:16:03 With θ\thetaθ a vector, the first derivative becomes the gradient and the second the Hessian HHH, the (n+1)×(n+1)(n+1) \times (n+1)(n+1)×(n+1) matrix of second partial derivatives Hij=∂2ℓ/∂θi∂θjH_{ij} = \partial^2 \ell / \partial\theta_i \partial\theta_jHij​=∂2ℓ/∂θi​∂θj​:

θ:=θ−H−1∇θℓ(θ).(3.12) \theta := \theta - H^{-1} \nabla_\theta \ell(\theta) . \tag{3.12}θ:=θ−H−1∇θ​ℓ(θ).(3.12)

1:17:22 That matrix is the catch. Each iteration solves a linear system in it, or inverts it, which is nothing for ten parameters and prohibitive for a hundred thousand. Ng’s rule of thumb follows: with ten or fifty parameters he would very likely use Newton’s method and be done in a few iterations; with ten thousand or more he would use gradient descent. The gap in iteration counts can be far larger than his hundred-to-ten. On the tumour data of Figure 3.2, which are nearly separable and so put the maximum far out at θ≈(−14.9,4.4)\theta \approx (-14.9, 4.4)θ≈(−14.9,4.4), Newton’s method reaches it to six decimal places in 9 iterations; gradient ascent with the safe fixed step α=4/λmax⁡(X⊤X)\alpha = 4/\lambda_{\max}(X^\top X)α=4/λmax​(X⊤X) needs about 117,000.
